# Code review, November 2026

Three independent reviewers (data and business logic; security and access; simplicity and tests) read the code without having seen it written. Every finding below was traced in the code; the data findings were reproduced with scripts. Status: **open** unless marked ✅ (fixed, with a test in `tests/review-*.test.ts`).

Overall: no critical issues and no way for an outside party in. The real risks are **money and warranty** (quotes or invoices at $0 when they should not be, totals that are off), a few **imports that can file data in the wrong place without saying so**, **hardening needed before the app goes on a company server**, and **duplicated logic** that would make the roles and editable-lists work risky.

## Kept as they are (reviewers agreed these are right)
Pure rule functions with every threshold passed in; plain SQL migrations with constraints; append-only corrections with a required reason; statuses worked out rather than stored; sign-in in one module; the importer design with maps proven against real files; the golden audit corpus; every server action and route checks permission; technicians do not get prices on any page; all SQL is parameterised; Docker runs as a non-root user; re-imports and double invoicing are blocked by unique constraints.
